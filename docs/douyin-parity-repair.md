# 抖音插件完整一致性修复与验收要求

整理日期：2026-11-04（Asia/Shanghai）。

用户目标：旧版实际可用的功能、界面内容、布局和交互行为在迁移版完整保留，达到“完全一样”。界面缺失属于必须修复的范围。

当前状态：差异分析与修复要求已整理，尚未实施本文所列修复。本次交付为需求总结、源码证据、修复清单和验收标准。

## 1. 基线与完成口径

旧版为独立插件 `dsh-douyin-life@0.2.9`，来源为 [dsh_douyin_tools](../../dsh_douyin_tools/package.json)，固定上游提交为 `aaf9f9a862afafd45a15acf32789da97688de695`。目标为个性化中心中的[抖音功能](../src/douyin/index.ts)。已有[迁移记录](douyin-migration.md)用于追踪历史实现和检查，不足以证明完整一致性。

此前根据“35 个工具、74 个配置字段、32 条路由、7 个标签页”宣布完整迁移，结论不成立。数量一致不能证明背后的调用、界面和结果一致。后续必须同时满足：

1. **功能一致**：旧版可达、可用的业务能力全部保留；按钮存在但调用链缺失，仍算未完成。
2. **界面一致**：入口位置、页签顺序、区域分组、状态信息、卡片内容、表单语义、条件展开和主要布局与旧版对齐。不能只保留七个页签或改为通用字段列表。
3. **交互一致**：保存时机、未保存输入、加载反馈、成功/失败反馈、扫码确认、刷新、超时和重试逐项对齐。
4. **行为一致**：相同配置和素材下，默认执行模式、账号动作组合、上下文来源、记忆写回、报告内容和调度结果一致。
5. **状态一致**：界面状态、保存结果和后台执行一致，不能保存成功但配置不起作用。
6. **数据连续**：验证旧数据导入后的登录、账本、报告、记忆和自定义资源；独立目录本身不是缺失，历史可见性仍需验收。
7. **证据完整**：需要行为验证和实际页面对照，不能只以类型检查、构建成功、入口计数或 Slot 注册宣布完成。

目标已有的数据根、打包、官方 SDK 和受控资源访问适配继续遵守项目约定。适配引入的可见差异必须记录原因和验收结果，不能默认视为已达到“完全一样”。

### F01：记忆管理界面

旧版可选记忆服务存在时，提供角色卡、时间线、清理和原始记录四个实际入口；服务不存在时回退本地记忆和人设。新版只保留本地记录及角色设定文本框。

证据：旧版[角色卡编辑及回读](../../dsh_douyin_tools/client.js#L1314)、[时间线搜索](../../dsh_douyin_tools/client.js#L1389)、[工作区清理](../../dsh_douyin_tools/client.js#L1427)、[可选服务回退](../../dsh_douyin_tools/client.js#L1532)；新版[记忆面板](../src/douyin/client/Panels.tsx#L22)。

必须恢复：称呼、时区、沟通风格、回复长度、约束的编辑与保存回读；记忆搜索及时间/类型展示；工作区展开、单条删除、整区清理及清理后回读；统计和原始记录元信息；本地人设编辑；服务缺失与失败反馈。共享角色卡和本地人设是不同来源，不能用一个文本框替代。

### F02：共享记忆业务连接

旧版私信先读取角色卡和共享上下文，失败时回退最近记忆；回复成功后将双方对话写回共享库。旧版评论也读取共享最近记忆。新版私信预留 sharedMemory 但正式入口未装配，对话写回只有本地文件；评论改读本地记录。

证据：旧版[私信读取](../../dsh_douyin_tools/index.js#L2445)、[对话写回](../../dsh_douyin_tools/index.js#L1456)、[评论读取](../../dsh_douyin_tools/index.js#L1340)；新版[入口装配](../src/douyin/index.ts#L32)、[私信上下文](../src/douyin/server/dm.ts#L79)、[本地写回](../src/douyin/server/memory.ts#L21)、[评论上下文](../src/douyin/server/replies.ts#L88)。

必须补齐真实依赖、读取回退、确认回复后的共享写回及服务不可用处理，并按旧版实际调用条件核验配置开关。用内容不同的共享/本地记忆替身，证明生成请求取得正确上下文，确认回复后实际触发共享写入。

边界：新版 Python 仍有[共享记忆接口](../resources/douyin/mcp/mcp_server.py#L3427)，headless 也仍保留记忆工具。缺失的是这些自动业务流程的连接，不能描述为底层能力全部删除。

### F03：默认执行模式

证据：旧版[工具模式选择](../../dsh_douyin_tools/index.js#L3820)、[页面运行入口](../../dsh_douyin_tools/index.js#L4191)；新版[工具处理器](../src/douyin/server/tools.ts#L51)、[运行路由](../src/douyin/server/routes.ts#L63)。

旧版谷时调度本来直接使用本机轮次，不将它误报为此次新增问题。

### F04：自动点赞组合

证据：旧版[评论或转发前点赞](../../dsh_douyin_tools/index.js#L3761)；新版[点赞受无其他互动模式条件限制](../src/douyin/server/local-round.ts#L77)。

## 4. 已排除的误报及未验证边界

1. 浏览器登录仍会启动 MCP，不能列为“按钮不启动浏览器”；真实登录仍待验收。
2. 谷时、随机巡检、续火花、私信、评论、人设与清理仍有调度实现，不列为整项删除；结果及边界仍需核验。
3. 旧版虽有图谱代码，但可达记忆页签没有图谱入口，不列为已确认缺失。发现实际入口后再补证据。
4. 旧版表情页展示索引和标签，未发现可用图片画廊，不将画廊计作迁移遗漏。
5. Python MCP 和视频理解脚本的顶层函数与参数签名未发现删减；不能由此推断内部行为完全等价。
6. ASR 模型及依赖的离线验证，不能证明浏览器采集、私信、评论或投稿通过真实账号验收。
7. 旧版已明确未接入的本机自动投稿、@豆包等能力，不能当作迁移删除；按旧版实际可用行为验收，界面也应准确表达限制。
8. 独立数据根属于既定适配；未导入的数据不能直接认定为 UI 删除，导入后的历史呈现必须检查。
9. 保留旧插件和旧数据。同名 ID、路由、工具及入口存在冲突，验证时隔离或顺序切换，不能同时启用冲突入口，也不能卸载旧插件回避对照。

## 6. 验证与最终完成条件

### 行为验证

使用临时目录、固定时间、确定性随机数及平台替身，重点覆盖：

- 共享服务有/无和读写失败；私信快回及 headless 回退；评论文本和图片。
- 默认/显式/非法运行模式、未保存配置及保存回读。
- 点赞与三类互动组合，理解失败、额度耗尽、跨日和发送状态未知。
- 扫码成功、超时、重试及切页后的请求和计时器清理。
- full/brief/off 报告内容与文件结果。
- 新选片进入人设观察区，人工正文保留。
- 独立/轮次分享，附言开关、固定附言、无转写回退和表情选择。
- 调度窗口、随机间隔、私信事件补漏、清理和卸载后停止。

断言关注输入、实际依赖调用和可见结果，不能只验证内部计划对象。

### 页面与视觉验证

相同数据、主题和窗口尺寸下逐页对照旧版和新版。因入口冲突采用隔离或顺序切换，保留旧插件及数据。每页检查正常、空态、加载、错误、保存后和未保存状态；开关检查开启和关闭后的条件显示。

截图验证实际渲染，交互记录验证按钮、自动轮询、表单及回读。Slot 存在、HTTP 成功和组件测试不能代替视觉验收。本轮没有实际 GUI 对照，必须保持待验收。后续修复须验证现有运行 GUI；启动另一个服务器不能证明当前 GUI 已更新。
