# 按三个功能组织源码，保留运行边界

用户确认个性化中心的源码顶层按外观、上下文与压缩、技能管理三个功能组织，
对应 `appearance/`、`tuning/`、`skills/`，技术职责在各功能内部划分。
这是对 ADR-0001 上一轮“稳定模块保持原位”范围的后续调整：允许移动稳定模块，保留原实现。

采用功能组织而不继续混用顶层技术分层，是为了让三个功能的代码归属直接可见，
代价是需要同步源码路径、测试及文档引用，并核对跨功能共享依赖。
迁移只涉及结构与引用，不改变功能、样式、接口、配置或生命周期；
Skills 既有内部拆分、子插件隔离及唯一写入队列保持稳定。
功能目录不要求成为独立子插件，也不要求重新划分运行时注册边界。

用户进一步确认保留 `src/index.ts`、`src/client/index.ts` 两个真实装配入口及构建、包入口路径。
外观和调优内部采用 client/server，纯逻辑直接位于功能根目录，Skills 内部结构不强制对齐。
共用 CSS 与两份宿主适配类型整文件归 shared，保留样式顺序及适配边界；
仅将媒体模块中实际跨功能使用的请求标记、回环判断提为共享约定，不统一各功能请求或守卫实现。
这接受了共享适配含部分功能专属类型和混合样式的现状，以降低迁移差分并避免碎片化。

逐文件映射和验收要求见 [完整方案](../feature-organization-plan.md)。
本记录表示上述范围决策已接受，不表示源码迁移已经实施。
