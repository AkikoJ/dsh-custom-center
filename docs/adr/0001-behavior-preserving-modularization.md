# 保留运行合同，在 Skills 子插件内部拆分职责

个性化中心已有独立的宿主入口、浏览器入口、纯逻辑和 Skills 子插件边界。
Skills 的两个主要实现文件分别达到 4,649 行和 3,958 行，修改会跨越多种业务和生命周期。
本次在 Skills 内部分出 server/client 职责模块，保留子插件隔离和实质入口，稳定模块保持原位。

用户要求功能和样式不变、单个手写源码/样式/测试文件不超过 800 物理行，并明确要求被拆界面转换 TSX。
新业务文件以 100–650 行为目标；合并同职责短文件，允许内部源码路径调整，不增加薄兼容转发文件。
不为行数下限给稳定配置、入口、SDK 声明和已有测试补行。

## 取舍

未选择全仓按技术类型重新分目录：它会扩大稳定模块和宿主接入面的变更，增加验证成本。
未选择保留全部旧内部深导入路径：合并短文件时会留下空壳；用户已明确允许内部路径调整。
未选择同步更换状态库、统一 IO 事务或修复既有行为：这些改变会扩大行为差分，妨碍纯重构验收。

core.ts 保留查询和 Provider 读模型编排；index.ts 持有宿主 Provider、工具、队列与生命周期。
浏览器插件入口持有注册和清理，视图状态保留原生命周期，拆出的展示 helper 用 TSX 表达。
内部职责模块禁止反向运行时依赖入口，避免兼容入口成为新的循环依赖中心。

## 后果

已知的守卫差异、保存失败提示、批量部分写入及重复扫描暂时保留，后续独立修复并单独验证。
TSX 转换要求同时核对 DOM、key/ref、状态挂载、CSS 内容、请求时序和真实宿主显示。
当前记录为 proposed；本次交付方案与词汇表，未修改运行源码。

完整迁移表和验收条件见 `docs/refactoring-plan.md`。
