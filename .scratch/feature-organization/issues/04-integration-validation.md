# 04: 三功能整体验收与文档交付

**What to build:** 交付可审查的三功能组织结果，使维护者能够确认结构约束、行为回归与文档一致性，并清楚区分自动检查证据、真实 DSH 验收结果及未完成项。

**Blocked by:** 02 — 外观功能完整迁移；03 — 上下文与压缩功能完整迁移。

**Status:** ready-for-human

**Type:** task

## 实施范围

依据父规格《按三个功能组织个性化中心源码》、定稿方案及 ADR-0002 完成集成验收与当前文档同步。
沿用前序任务建立的本轮基线和验证记录，历史方案、历史 ADR 与上一轮验证记录保持其历史含义。

- [x] 三个功能归属完整，Skills 的内部结构、TSX 界面、Provider、工具、唯一写入队列、状态格式与子插件隔离保持稳定。
- [x] 原技术分层中的被迁声明均有唯一去向；空旧层级移除，保留两个真实装配入口，不新增功能聚合入口或空壳兼容模块。
- [x] 当前源码、测试、配置和双语说明没有非预期旧路径引用，历史文档中的旧路径不误删；包导出、构建入口、类型入口与预期产物位置保持原配置。
- [x] 解析并核对运行时导入导出图：无环，共享边界不依赖功能或入口，外观与上下文与压缩互不依赖，浏览器不可达 Node 或服务端运行实现；SDK 类型来自正式 npm 包。
- [x] 对照本轮基线核对运行声明、组件挂载、注册与清理顺序、接口合同和静态资源；共用 CSS 最终字符串摘要一致，拼接和注入行为一致，Skills 的 CSS 与词典回归通过。
- [x] 通过完整无产物类型检查、全量既有测试及差异空白检查；仅在确有行为覆盖缺口时补必要测试，不创建逐文件镜像测试或新增测试框架。
- [x] 全量统计手写源码、声明、样式、测试及根 TypeScript 配置的物理行数，报告文件总数、最大行数和超限文件；任一文件超过 800 行即未通过，不通过压缩排版规避。
- [x] 全量 Skills 回归覆盖用户与项目作用域、策略、Provider 选择、导入与回收站、同步、HTTP 与工具共用队列、会话切换、过期响应及卸载清理；记录实际执行结果。
- [x] 中英文当前目录说明同步更新；更新项目规则的布局说明前读取适用写作技能和最新规则，只作最小同步，保留用户新增内容；领域词汇表不作无关调整。
- [ ] 真实 DSH 验收对照相同宿主版本、数据、主题及窗口条件，检查三个导航项、外观预览与恢复、保存、图片与视频、调优范围与预设操作、Skills 基本操作、焦点、Escape、浅深主题、窄宽窗口与热重载清理。
- [x] 缺少真实宿主或对照基线时，将对应验收明确记为未完成；需要新产物时先获得明确构建授权，不以静态一致性或测试通过宣称最终 bundle 和视觉交互已验证。
- [x] 本轮验证记录及交付报告列出实际移动与提取、共享边界、各阶段检查、行数、类型与测试结果、依赖验证、环境限制、真实宿主结果和未完成项，不复用历史结果冒充本轮证据。
- [x] 保留用户已有改动与真实数据，不修改 DSH 宿主源码、依赖、锁文件、许可证及已有产物；不自动构建、提交或推送。
