# 按三个功能组织个性化中心源码

Status: ready-for-agent

## Problem Statement

个性化中心提供外观、上下文与压缩、技能管理三个功能页面，但源码采用混合组织方式：
外观与上下文与压缩分散在浏览器、宿主和纯逻辑层，技能管理则作为完整功能独立组织。
维护者无法从顶层结构直接找到一个功能的全部实现，修改和审查时需要在技术层之间反复定位。

上一轮已经完成 Skills 职责拆分及界面 TSX 转换；本轮需要统一三个功能的源码归属，
同时保留现有功能、样式和实际运行行为，避免目录调整引起接入、交互或持久化回归。

## Solution

按外观、上下文与压缩、技能管理组织源码，在各功能内部区分浏览器与宿主职责。
纯逻辑留在所属功能内，确实跨功能复用的配置、样式、宿主适配和请求约定归入共享边界。
保留现有宿主与浏览器装配入口、插件运行边界及 Skills 内部稳定模块。

对用户而言，三个页面的名称、顺序、样式、操作与保存结果保持一致；
对维护者而言，每个功能的实现位置更清晰，依赖方向可检查，手写文件均不超过 800 物理行。
本轮采用结构迁移，同步引用、测试导入和文档，不夹带功能修复或行为优化。

## User Stories

1. 作为插件维护者，我希望顶层源码清楚对应三个功能，以便直接找到所负责功能的实现。
2. 作为外观功能维护者，我希望页面、壁纸控制与素材接口按功能集中，以便审查完整外观行为。
3. 作为上下文与压缩功能维护者，我希望页面、模型窗口计算和配置接口按功能集中，以便追踪修改的完整影响。
4. 作为技能管理维护者，我希望保留已有内部拆分，以便避免重复调整已稳定的模块。
5. 作为插件维护者，我希望浏览器、宿主与纯逻辑边界清晰，以便避免平台依赖进入错误的运行环境。
6. 作为插件维护者，我希望只有真正跨功能复用的能力进入共享边界，以便避免形成新的杂项模块。
7. 作为插件维护者，我希望调优专用选择控件留在调优功能内，以便代码归属符合实际使用关系。
8. 作为插件维护者，我希望整份共用样式保持原注入方式，以便目录调整不影响样式覆盖顺序。
9. 作为插件维护者，我希望请求标记和回环判断保持唯一实现，以便两个功能使用同一约定而不互相依赖。
10. 作为代码审查者，我希望迁移差异集中在位置和引用，以便确认原实现没有被顺带修改。
11. 作为代码审查者，我希望每个文件不超过 800 物理行且没有空壳转发，以便保持单文件可读性与真实职责边界。
12. 作为 DSH 用户，我希望三个设置页面的导航名称、顺序和图标保持一致，以便沿用现有操作习惯。
13. 作为 DSH 用户，我希望插件总开关与技能开关保持原默认值和效果，以便现有设置继续生效。
14. 作为外观用户，我希望草稿预览和退出预览的恢复行为保持一致，以便安全调整视觉偏好。
15. 作为外观用户，我希望已保存设置及重新打开页面后的结果保持一致，以便避免偏好丢失。
16. 作为外观用户，我希望图片和视频壁纸继续使用现有本地存储，以便无需重新选择或迁移素材。
17. 作为壁纸库用户，我希望上传、列表、重名处理和素材读取保持一致，以便继续管理已有素材。
18. 作为壁纸库用户，我希望视频分段读取和媒体类型判断保持一致，以便壁纸播放继续正常工作。
19. 作为 DSH 用户，我希望配色、遮罩、输入框不透明度与正文加强保持一致，以便保留原有显示效果。
20. 作为 DSH 用户，我希望浅深主题及不同窗口尺寸下的显示保持一致，以便日常使用不受迁移影响。
21. 作为键盘用户，我希望选择控件、菜单和弹窗的焦点与 Escape 行为保持一致，以便继续通过键盘完成操作。
22. 作为上下文与压缩用户，我希望模型窗口及输出预留容量的校验和显示保持一致，以便获得相同的配置结果。
23. 作为上下文与压缩用户，我希望单模型、供应商与全部模型的应用范围保持一致，以便修改只作用于既定目标。
24. 作为上下文与压缩用户，我希望 Agent 预设的自动压缩设置保持一致，以便压缩策略继续按预设生效。
25. 作为上下文与压缩用户，我希望请求失败和批量写入结果遵循原有语义，以便结构调整不改变操作反馈或实际生效顺序。
26. 作为技能管理用户，我希望技能来源、启停和分类行为保持一致，以便继续使用当前本地策略。
27. 作为技能管理用户，我希望用户作用域与项目作用域保持隔离，以便操作不会影响其他目标位置。
28. 作为技能管理用户，我希望创建、编辑、导入、同步及回收站操作保持一致，以便继续管理已有技能内容。
29. 作为技能管理用户，我希望同名技能选择、其他 Agent 来源只读规则和同步状态保持一致，以便内容来源与结果仍可判断。
30. 作为 DSH 集成维护者，我希望现有插件标识、注入服务、接口和工具合同保持一致，以便宿主无需同步改造。
31. 作为 DSH 集成维护者，我希望 Skills 的服务隔离、Provider 与唯一写入队列保持一致，以便并发操作和可用性不发生变化。
32. 作为 DSH 集成维护者，我希望主题订阅、按请求解析服务及热重载清理保持一致，以便避免重复注册或遗留监听。
33. 作为测试维护者，我希望沿用既有行为测试和高层入口，以便验证真实结果而不为每个移动文件新增测试接缝。
34. 作为项目维护者，我希望中英文目录说明同步更新，以便后续开发者看到一致的结构说明。
35. 作为工作区所有者，我希望已有未提交改动得到保留，以便规划和迁移不覆盖其他工作。
36. 作为项目维护者，我希望交付报告区分自动检查与真实宿主验收，以便准确了解证据范围和未完成项。
37. 作为工作区所有者，我希望构建、提交和推送继续遵守明确授权要求，以便掌握产物生成和版本发布时机。

## Implementation Decisions

- 采用按功能组织的后续重构，三个功能分别为外观、上下文与压缩、技能管理。
- 外观与上下文与压缩内部区分浏览器和服务端；纯逻辑直接归所属功能，不额外增加空层级。
- 保留两个真实装配入口、构建入口、包入口、声明入口和预期产物位置；不为目录对称新增功能子插件。
- 原顶层技术层中的功能实现完整迁移，所有原声明有唯一归属；只更新位置、必要引用、测试导入和当前文档。
- 保留模块和声明名称，不增加聚合导出、旧路径空壳兼容模块、通用工具杂项模块或额外状态容器。
- Skills 保留现有内部结构、TSX 界面、子插件隔离、Provider、工具、队列与生命周期，不强制与其他功能统一内部命名。
- 外观包含页面、控制器、壁纸存储、壁纸库请求与接口、颜色、皮肤、取色及媒体规则。
- 上下文与压缩包含页面、专用选择控件、请求、模型窗口和压缩计算及配置接口；专用选择控件不提为共享组件。
- 全插件开关配置、整份共用样式、浏览器宿主适配及 Node 宿主适配整体归共享边界。
- 共用样式保留最终 CSS 字符串、拼接顺序、注入条件和注入时机；不按功能切割混合规则。
- 宿主适配类型保持整块，允许其中含少量功能专属服务形状，以保持对接边界并避免短类型文件碎片化。
- 只从媒体规则中提取实际跨功能使用的请求标记和回环判断，保持原值及原函数逻辑；其他媒体规则归外观。
- 两个共享声明由消费者直接引用其新所属模块，不通过媒体模块转发；它们构成真实共享职责，允许文件较短。
- 外观与上下文与压缩不能互相依赖；共享实现不能反向依赖任何功能或装配入口；运行时依赖图不得成环。
- 浏览器运行时不能到达 Node 或服务端实现；宿主类型采用纯类型引用，SDK 类型只来自正式发布的 npm 包。
- 插件名称、注入服务、开关 schema 和默认值、导航标识、顺序及组件挂载边界保持不变。
- 控制器创建、插槽注册、主题监听、样式注入和清理顺序保持不变；宿主服务仍按原时机解析。
- 壁纸库接口、调优接口及 Skills 接口的原路径、方法、请求头、状态码、字段、错误和校验顺序保持不变。
- 不新增接口或 schema，不迁移配置与业务数据，不改变本地存储键、目录、回收站格式及其他持久化合同。
- 保留素材读取的 Range 行为、文件大小限制、路径和链接校验、环境变量求值时机及当前各路由守卫差异。
- 保留草稿、预览、已保存设置及错误提示的现有状态归属、更新顺序和异步语义。
- 保留模型窗口应用范围、Agent 预设压缩策略、批量写入顺序及中途失败可能部分生效的现有语义。
- 保留 Skills 用户作用域与项目作用域、来源只读规则、同名覆盖、同步、分类、回收站及失效通知语义。
- 允许内部源码路径调整，仓内消费者同步更新；保留包的源码通配导出配置，但不承诺旧内部深路径继续存在。
- 已有本地消费者排查未发现对当前插件旧源码的深导入；实施前复核可访问消费者，若发现真实仓外依赖，先报告影响再决定兼容范围。
- 物理行数包含导入、声明、注释和空行；全部手写源码、样式、测试及根 TypeScript 配置均不得超过 800 行，不通过压缩排版规避。
- 以完整模块移动为主，不继续拆分符合限制的稳定模块；不做全仓格式化、算法优化或依赖升级。
- 按基线记录、共享边界、外观迁移、调优迁移、收尾验收五阶段推进；阶段不是自动提交边界。
- 同步中英文当前目录说明，对项目规则中的旧布局描述作最小更新，保留用户新增内容；历史方案、ADR 和验证记录保留原历史含义。
- 本轮采用 ADR-0002 确认的范围，作为 ADR-0001 中上一轮稳定模块原位策略的后续调整；功能与运行合同继续冻结。
- 不修改 DSH 宿主源码，不自动构建、提交或推送；保留工作区已有用户改动。

## Testing Decisions

- 测试接缝沿用用户已确认最终方案中的现有边界，无新增待确认接缝：以插件对浏览器和宿主暴露的行为合同为验收视角，在既有 HTTP 路由工厂、配置写入适配和页面行为处验证。
- 优先使用最高的现有接缝；壁纸库以请求、响应和临时素材目录结果验证，调优以路由输入、响应及宿主配置结果验证，Skills 沿用现有路由、工具及行为测试。不为每个被移动的内部函数新增接缝。
- 好的测试关注可观察的结果、错误、授权拒绝、副作用和时序，不绑定私有实现、模块移动细节或内部调用次数；既有测试意图保持不变。
- 既有测试保留原组织，只更新源码导入；媒体与回环判断的测试可以留在同一测试组文件中，分别引用新所属模块。
- 沿用现有 Vitest：壁纸库已有真实本地 HTTP 请求测试，调优已有可控服务适配的路由测试，Skills 已有路由、文件、策略、同步、数据与异步生命周期测试。
- 继续运行现有颜色、皮肤、取色、配置、媒体和调优计算测试作为确定性输出回归，不为迁移新增重复的逐函数测试。
- 对确实缺失且本轮可能影响的行为，优先补在现有最高层接缝；不新增测试框架、运行时适配或通用测试抽象。
- 实施前检查脚本，确认类型检查不生成产物、测试不触发构建；先记录当次基线，逐阶段运行相关测试，收尾执行完整类型检查与测试。
- 测试使用临时目录与可控服务，不写用户真实素材、技能和配置。监听本地端口受环境限制时分别报告，不修改产品行为以绕过限制。
- 壁纸库回归覆盖上传、重名、类型和签名、列表、Range、路径逃逸、符号链接、请求标记、Connection 拒绝及方法限制。
- 调优回归覆盖当前模型与预设读取、窗口和压缩写入、应用范围、参数拒绝、未知目标及原先写入顺序与失败语义。
- Skills 继续覆盖作用域隔离、策略迁移、Provider 选择、导入与回收、同步、HTTP 和工具共用队列、会话切换、过期响应与卸载清理。
- 页面和真实宿主验收检查三个导航项、外观预览与恢复、图片和视频、调优操作、技能基本操作、焦点、浅深主题、窗口尺寸和热重载清理。
- 在相同宿主版本、数据、主题和窗口条件下对照 DOM、属性与可见效果；没有真实宿主或对照基线时明确记为未完成。
- 对共用样式记录最终 CSS 摘要并比对迁移前后，同时检查注入行为；保留 Skills 现有 CSS 和词典回归。静态一致性证据不能替代真实交互验收。
- 单独执行结构验收：逐文件行数、旧路径残留、声明归属、运行时依赖环、浏览器平台边界、跨功能依赖及入口配置。此类检查验证组织约束，不替代行为测试。
- 为路径调整执行必要的声明及静态资源基线比较，不以新增逐行 AST 测试代替行为断言。
- 不自动执行构建。若真实宿主需新产物才能验证，先取得明确构建授权；未构建时不得宣称已验证最终 bundle。
- 当前只读盘点为 14 个测试文件、132 个测试声明；它不是本次运行结果，实施报告使用实际执行的数据。

## Out of Scope

- 新增、删除或改变三个功能页面及其用户操作。
- 修复现有守卫差异、保存失败提示、批量写入部分生效或其他已知行为问题。
- 重写 Skills、扩大 TSX 转换范围、调整其内部模块边界、Provider、工具、队列或会话生命周期。
- 将功能目录变成新的独立子插件，或重新组织 DSH 宿主的插件注册机制。
- 统一全部请求实现、错误封装、来源校验、IO 事务、状态管理或样式系统。
- 为旧内部路径新增空壳转发层，或无条件承诺无法排查的外部源码深导入兼容。
- 增加运行时依赖、迁移框架、缓存、持久化格式或自动化发布流程。
- 修改 DSH 宿主源码、已有生成产物、锁文件、许可证及不受本次迁移影响的配置。
- 在本次规格发布过程中执行源码迁移、测试、构建、提交、推送或部署。
