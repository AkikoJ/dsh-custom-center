# 抖音账号登录与宿主内部凭据

Status: ready-for-agent

## Problem Statement

用户希望先在个性化中心完成抖音登录，并将登录所得的 Cookie 留给宿主后续发起 HTTP 请求。目前中心只有外观、上下文与压缩、技能管理，没有抖音账号入口、登录会话管理或内部认证资料。

两个参考插件分别使用 Node.js CDP 和 Python Playwright，但不能直接等同于本项目所需的可靠登录能力：部分流程在浏览器尚未实际启动时就返回成功，部分登录判定依赖 Cookie 名称或头像，部分 Cookie 导出丢失域与路径条件。用户需要确认登录的是哪个抖音账号、凭据是否保存成功，以及这些凭据是否真的可以用于独立 HTTP 请求。

当前只解决登录基础，不实现私信读取或回复。用户已明确 Cookie 仅供宿主内部调用，不需要下载或在页面中展示。

## Solution

在个性化中心新增独立「抖音账号」设置页。用户点击「打开登录窗口」后，宿主使用 Node.js + Playwright 配套 Chromium 打开真实抖音网页，用户自行完成扫码、手机确认、短信或网页验证码。

宿主通过平台返回的当前账号身份确认登录，保存保留 Cookie 属性的内部凭据快照，再使用独立的 Node HTTP 客户端验证相同账号 UID。页面分别展示浏览器认证、凭据保存、HTTP 可用性和窗口状态，让用户能区分登录成功、保存失败、HTTP 暂不可确认等情况。

一期限定 macOS 本机单账号。关闭窗口保留抖音登录会话，重复操作复用受管理的浏览器。浏览器登录已确认但 HTTP 暂时失败时保留会话，显示「HTTP 待验证」；功能交付仍必须包含至少一次真实独立 HTTP 同 UID 验证成功的证据。

## User Stories

1. 作为个性化中心用户，我希望在设置中找到独立的抖音账号页面，以便集中查看和操作登录状态。
2. 作为首次使用者，我希望打开页面只读取当前状态，以便不会未经操作就启动浏览器或安装软件。
3. 作为 macOS 用户，我希望使用插件明确支持的本机登录流程，以便获得经过实际验证的行为。
4. 作为用户，我希望点击打开登录窗口后真的出现抖音网页，以便立即进行登录而不是收到虚假成功提示。
5. 作为用户，我希望使用与 Playwright 匹配的配套 Chromium，以便无需依赖本机安装的 Google Chrome。
6. 作为用户，我希望浏览器未准备好时看到明确的准备提示，以便知道如何恢复登录入口。
7. 作为用户，我希望浏览器启动失败与抖音页面加载失败分别反馈，以便采取正确的重试操作。
8. 作为用户，我希望通过抖音真实网页扫码登录，以便沿用平台已有的认证流程。
9. 作为用户，我希望扫码后可以在手机确认登录，以便不会被插件提前认定为成功或失败。
10. 作为需要短信验证的用户，我希望直接在抖音窗口填写验证码，以便不必将验证码交给插件表单。
11. 作为遇到网页安全验证的用户，我希望在原窗口完成验证，以便保留已进行的登录步骤。
12. 作为用户，我希望插件无法识别具体验证类型时仍允许继续操作网页，以便辅助检测不会阻碍真实登录。
13. 作为用户，我希望等待扫码时页面显示清楚的操作提示，以便知道应在浏览器还是手机继续。
14. 作为用户，我希望重复点击打开登录窗口时复用当前窗口，以便不会产生多个登录实例。
15. 作为用户，我希望并发检查不会打断正在进行的登录，以便重复操作不会造成会话混乱。
16. 作为已经登录的用户，我希望再次打开窗口能恢复原有会话，以便不必每次重新扫码。
17. 作为用户，我希望手动检查当前登录状态，以便自动观察暂停后仍可继续流程。
18. 作为用户，我希望长时间未完成登录时仅暂停自动观察，以便原窗口和已完成步骤仍然保留。
19. 作为用户，我希望只有平台确认当前账号身份后才显示已验证登录，以便 Cookie 或头像假象不会误导我。
20. 作为用户，我希望看到当前抖音账号的身份摘要，以便确认后续请求将归属于正确账号。
21. 作为用户，我希望昵称缺失时仍能依据账号 UID 判断身份，以便展示信息不完整不会造成错误归属。
22. 作为用户，我希望登录完成后宿主保存可用于请求的抖音登录凭据，以便后续功能能够复用认证资料。
23. 作为用户，我希望浏览器登录与凭据保存分别反馈，以便保存失败时不会被误导为全部完成。
24. 作为用户，我希望保存失败后保留上一份完整资料并能重试，以便不会得到损坏或半份凭据。
25. 作为用户，我希望 Cookie 仅供宿主内部使用，以便页面、下载接口和普通状态响应不会暴露认证资料。
26. 作为用户，我希望日志和 Agent 上下文不包含凭据，以便账号认证资料不会随诊断记录扩散。
27. 作为用户，我希望 HTTP 验证脱离浏览器独立执行，以便确认保存的 Cookie 确实能服务于宿主请求。
28. 作为用户，我希望 HTTP 验证确认相同 UID，以便不会将另一个账号的认证资料标记为可用。
29. 作为用户，我希望 HTTP 验证结果绑定具体凭据版本和时间，以便知道结论对应哪一次登录资料。
30. 作为用户，我希望 HTTP 临时网络失败时保留浏览器登录，以便不必无意义地反复扫码。
31. 作为用户，我希望限流、挑战页和认证拒绝等情况有可理解的区分，以便判断应等待、重试还是查看浏览器。
32. 作为用户，我希望发现 HTTP 身份不一致时停止使用该凭据，以便避免后续操作属于错误账号。
33. 作为用户，我希望 Cookie 更新后重新判断 HTTP 可用性，以便不会继续看到上一版本的验证结论。
34. 作为用户，我希望关闭窗口后保留抖音登录会话，以便以后能够继续使用已登录账号。
35. 作为用户，我希望关闭操作可以重复执行，以便已关闭窗口不会使页面进入不可恢复的错误状态。
36. 作为用户，我希望登录完成后不会突然关闭窗口并切换无头浏览器，以便已完成的认证流程保持稳定。
37. 作为用户，我希望宿主重启后能看到上次保存资料与当前验证状态的区别，以便不会把历史成功误认为当前有效。
38. 作为用户，我希望明确未登录时停止向业务提供过期凭据，以便后续功能不会继续使用失效认证资料。
39. 作为用户，我希望不同 DSH profile 的会话资料相互隔离，以便不会发生账号串用。
40. 作为用户，我希望独立浏览器不占用日常 Chrome profile，以便个人浏览器数据不受插件影响。
41. 作为用户，我希望 profile 已被占用时得到明确提示，以便插件不会强行关闭其他进程或破坏会话文件。
42. 作为用户，我希望遇到另一个账号 UID 时停止自动覆盖，以便一期单账号资料不会被静默替换。
43. 作为用户，我希望仅允许受认证的本机页面操作登录功能，以便跨来源请求无法启动窗口或读取账号资料。
44. 作为用户，我希望浏览器依赖故障不影响外观、上下文与压缩和技能管理，以便其他功能继续可用。
45. 作为用户，我希望离开设置页后停止页面刷新请求，以便不会留下无用轮询。
46. 作为用户，我希望插件卸载、热更新和宿主停止时清理所属资源，以便不会留下重复任务和争抢 profile 的浏览器。
47. 作为维护者，我希望旧异步任务无法覆盖新状态，以便关闭、重开和热更新后仍保持正确的账号归属。
48. 作为维护者，我希望测试从用户可观察的宿主接口验证行为，以便内部重构不会导致大量无意义测试变更。
49. 作为维护者，我希望真实 Chromium 部署和独立 HTTP 验证有明确验收记录，以便不会将模拟测试结果误当作上线可用证据。
50. 作为后续账号功能维护者，我希望复用有明确账号归属及有效性边界的内部凭据，以便将来新增私信能力时不必重写登录基础。
51. 作为用户，我希望明确知道登录验证不等于私信接口已可使用，以便对当前交付能力形成准确预期。
52. 作为项目所有者，我希望本次规格整理不执行实现、构建、安装或提交，以便按独立步骤推进后续开发。

## Implementation Decisions

- 遵循既有功能组织原则，新增独立抖音账号功能，包含浏览器 UI、宿主登录编排、浏览器适配、身份验证、内部凭据存储和 HTTP 客户端。宿主与浏览器入口只增加装配，其他功能不依赖抖音业务。
- 遵循 ADR-0003：由本中心独立拥有登录会话；两个旧插件只作机制和缺陷参考，不运行时导入其实现，不共享其浏览器或 Python/MCP 进程。
- 使用 Node.js + Playwright，而非手写 CDP 封装或额外 Python 服务。该选择服务于现有 TypeScript/Node 宿主集成，不代表两种语言的浏览器能力不同，也不代表可以规避平台的 HTTP 认证要求。
- 使用与 Playwright 版本匹配的配套 Chromium。插件依赖与浏览器二进制分别准备，浏览器准备属于明确的安装步骤，不在访问页面或点击登录时静默下载。具体依赖版本在实施时锁定并验证部署资源完整性。
- 浏览器能力延迟加载，失败隔离于抖音功能；缺少 Chromium 不得使现有其他功能注册失败。
- 每个宿主登录服务实例持有一个专用、可见、持久浏览器上下文，固定导航到抖音登录所需页面，禁止使用个人日常浏览器 profile。创建客户端对象或提交启动任务不算开窗成功。
- 复用现有设置页插槽和主题样式约定，提供打开登录窗口、检查登录状态和关闭登录窗口三个操作。页面不嵌入自行托管的登录 HTML，不提供密码、验证码或 Cookie 输入框。
- 开窗、检查、保存、关闭由一个服务实例协调并发；重复开窗复用现有上下文，重复检查合并或串行。关闭操作幂等，保留持久会话，不自动切换无头浏览器。
- profile 占用时明确失败，不删除浏览器锁文件、不杀其他浏览器进程。关闭窗口、插件卸载、宿主停止与热更新必须取消所属任务并释放受管理资源；旧任务通过代次控制失去写回资格，新实例等待旧上下文释放后才可重用 profile。
- 使用平台当前账号只读响应中的业务成功结果及非空 UID 确认身份。Cookie 非空、头像、昵称和 Cookie 中的用户字段只能作为辅助证据，不能替代身份验证。若没有可信身份响应，状态保持待确认。
- 参考项目使用的当前账号接口只作为候选，在实施前验证实际方法、参数、响应和可用性；不将历史注释中无需签名的说法当作事实。如果接口需要当前范围之外的协议工作，应记录阻塞而不是降低认证标准。
- 浏览器身份确认后，通过浏览器上下文读取包含 HttpOnly Cookie 的资料，原子保存内部凭据快照。快照包含 schema 版本、凭据代次、账号 UID、可选昵称、导出时间、浏览器验证时间、User-Agent 和完整 Cookie 属性。
- Cookie 保留名称、值、域、路径、到期时间、HttpOnly、Secure、SameSite，以及浏览器提供的相关扩展属性。区别会话 Cookie、持久 Cookie和 host-only/domain 匹配；不把不支持的分区 Cookie 降级成普通 Cookie。
- 优先使用成熟 CookieJar 实现请求匹配。只收集明确允许的抖音域，按协议、域、路径、过期和重名规则生成目标请求的 Cookie，不使用域名子串匹配或跨域扁平拼接。重定向逐跳校验目标，不向未知域转发凭据。
- 凭据保存在服务端决定、按 DSH profile 隔离的固定数据根内；无 profile 时使用明确的宿主数据根回退。页面不得指定目录或文件。身份和 Cookie 以单份版本化快照提交，采用临时写入后原子替换，macOS 下限制为当前用户可读写，拒绝越界写入。
- 保存失败保留上一份完整快照，并明确标记本次失败；损坏或不支持版本的快照不能提供给业务。profile 与凭据不进入版本控制、页面状态、日志或 Agent 上下文。
- 独立 HTTP 验证使用 Node HTTP 客户端和已保存的 CookieJar，不借用浏览器上下文共享认证的请求能力。仅在业务成功且 UID 与浏览器相同时显示 HTTP 已验证，结果绑定账号 UID、凭据代次和验证时间。
- User-Agent 作为请求上下文保存，但不盲目复制所有浏览器请求头，不承诺 Cookie 加 User-Agent 足以支持所有平台接口。HTTP 更新 Cookie 后形成新凭据代次，旧验证结论不能自动应用到新代次；不实现浏览器与 HTTP 的通用双向 Cookie 同步。
- 分别记录操作阶段、浏览器认证、凭据保存、HTTP 验证及窗口开闭。临时网络失败不直接撤销浏览器登录；明确未登录使凭据过期并停止内部消费；HTTP UID 不一致拒绝该代次的内部使用；发现其他账号 UID 时不自动覆盖一期账号。
- 重启后展示上次保存摘要但将当前认证视为未验证，不能仅因文件存在恢复有效结论。本次登录完成要求浏览器身份确认且凭据保存成功；HTTP 暂不可确认独立展示，不把它伪装成全部可用。
- 自动观察采用有界轻量轮询与串行身份验证。初始参数沿用计划：轻量观察间隔约 3 秒，身份验证至少间隔 10 秒并对临时失败退避，单次网络请求约 15 秒超时，等待用户约 10 分钟后暂停观察并保留窗口。页面卸载取消页面请求，重新挂载只查询状态。
- 沿用宿主路由合同，增加 GET 状态、POST 开窗、POST 检查及 POST 关窗四项操作；状态查询不启动浏览器，检查负责身份确认、保存和必要的 HTTP 验证，响应只包含脱敏结果。
- 路由统一要求回环 socket、宿主认证及来源校验通过、同源浏览器请求标记；响应禁止缓存，不启用跨域凭据访问。请求不接受任意 URL、文件路径、浏览器执行路径、JavaScript 或通用代理参数。
- 一期只在宿主内调用认证能力，暂不发布跨插件凭据服务或 Agent 工具。将来跨插件集成使用正式 Cordis 服务或插槽合同，不直接引用兄弟插件内部实现。
- 实施顺序先证明 Chromium 部署、浏览器身份和独立 HTTP 同 UID 链路，再完成宿主编排、设置页、异常恢复和回归。既有架构规则扩展覆盖新功能，中英文功能说明同步更新。

## Testing Decisions

- 用户已确认以现有宿主 HTTP 路由为主要自动化测试入口，贯穿真实登录编排、凭据持久化与 HTTP 验证。测试关注响应、可观察状态、最终文件结果及出站请求，不断言私有方法、文件拆分、选择器写法或内部调用顺序。
- 优先复用壁纸库现有的本地 HTTP 服务与真实临时目录测试方式，以及调优宿主接口现有的请求、响应和拒绝注入方式。新的测试入口集中在抖音路由组合处，不为每个内部模块新增测试专用公共接口。
- 主链路保留真实业务编排、CookieJar 和临时目录，只在浏览器/抖音平台外部适配边界提供可控替身。测试通过受控外部响应制造扫码等待、平台成功、认证拒绝、限流和 UID 不一致，不 mock 掉整段登录服务再仅检查返回值。
- 从主入口观察开窗完成、重复操作、身份确认、凭据保存及 HTTP 验证；浏览器替身须区分启动、导航、关闭和身份结果，以捕捉只构造对象就返回成功的旧缺陷。
- HTTP 测试使用独立的可控网络边界，观察请求实际携带的 Cookie 和响应身份；测试传输适配仅由测试宿主组合，不对生产页面开放任意 URL。验证同 UID 成功、异 UID 拒绝、临时失败不撤销已确认登录，以及凭据代次更新后旧结论失效。
- 文件结果使用临时目录观察快照完整性、账号与 Cookie 同代次、权限、保存失败后旧资料完整、损坏及未知 schema 拒绝、不同 profile 隔离；不读取或写入用户真实账号资料。
- Cookie 场景覆盖域边界、host-only、子域、路径、重名、过期、Secure、会话 Cookie、分区属性和跨域重定向。对具有可观察结果的协议边界补充针对性测试，不复制 CookieJar 库自身实现作为测试断言。
- 生命周期测试复用已有 Cordis effect 清理、客户端延迟响应失效及外观控制器卸载测试的经验，观察关闭、卸载、热更新后无重复窗口和请求、无旧任务覆盖、profile 争抢可诊断，避免为每个 helper 制造新的测试接缝。
- 页面卸载与状态展示若无法由宿主路由覆盖，仅补充必要的高层页面/控制器行为测试，沿用现有客户端并发与清理模式；真实设置页渲染、按钮反馈和窗口操作纳入人工验收，不把模拟 React 调度当作真实宿主视觉证据。
- 路由测试必须覆盖非回环、未认证、跨来源、缺失标记、非法方法和输入，并检查拒绝请求不启动浏览器或泄露凭据。状态和错误响应不得包含 Cookie 值、验证码、Token 或完整平台响应。
- 继续使用既有架构检查确认浏览器侧无 Node/服务端依赖、功能之间无反向引用、共享模块不依赖功能及源码无环；新增功能必须进入识别范围，不能因未被规则枚举而漏检。
- 代码实现后优先运行 noEmit 类型检查和与变更相关的测试，再在已有其他功能上进行必要回归。本轮仅发布规格，不运行实现测试、浏览器、构建或安装；未来构建仍须用户明确要求或批准。

验收以以下外部结果为准：

| 场景 | 可观察的通过条件 |
| --- | --- |
| 首次登录 | 真正打开配套 Chromium 和固定抖音页，等待用户操作 |
| 缺浏览器、启动或导航失败 | 准确错误及恢复提示；其他中心功能可用 |
| 扫码、手机确认、短信或验证码 | 在同一真实窗口继续完成；不因提示识别失败而重置流程 |
| Cookie/头像存在但身份未确认 | 不宣称已验证登录 |
| 浏览器身份与凭据成功 | 正确 UID、完整快照、页面不返回认证资料 |
| 独立 HTTP 成功 | 普通 Node HTTP 请求返回同 UID，验证结果绑定该凭据代次 |
| HTTP 临时失败 | 已确认浏览器登录和完整快照保留，显示 HTTP 待验证及原因 |
| HTTP UID 不一致或明确未登录 | 停止提供相应凭据，不覆盖正确账号或静默切换 |
| 保存失败、快照损坏 | 不发布半份资料或伪造本次成功，可诊断和重试 |
| 并发点击、关窗、HMR 或 profile 占用 | 一个受管理上下文，资源正确释放，无过期写回和强制杀进程 |
| 关窗及宿主重启 | 会话资料保留，区分历史保存与当前有效性 |
| 域与路径不匹配、重定向越界 | 无关目标收不到账号 Cookie |
| 未授权请求或恶意输入 | 在产生浏览器或文件副作用前拒绝，响应不泄露凭据 |

最终在 macOS 本机 DSH 人工验收真实设置页、配套 Chromium 安装及版本匹配、用户实际扫码/网页验证、关窗恢复和重启语义；至少完成一次浏览器身份与独立 Node HTTP 同 UID 验证。记录版本、环境、时间和脱敏结果。模拟测试通过不代替这些运行证据；尚未验证的步骤不能标记交付完成。

## Out of Scope

- 私信未读检查、消息列表、会话读取、自动回复和发送消息。
- 私信 HTTP 协议逆向、签名算法、WebSocket、长连接及完整平台 API 封装。
- 多账号管理、账号切换、退出账号、清除会话和账号资料迁移。
- Cookie 下载、复制、导入、前端明文展示或对外凭据 API。
- 独立二维码截图面板、插件内短信填报、验证码自动处理和认证绕过。
- Python/MCP 运行时引入、手写通用 CDP 控制器、复用旧插件浏览器进程。
- 本机 Google Chrome 回退、静默下载浏览器、修改日常浏览器 profile。
- Windows/Linux 支持承诺、远程登录服务及通用 HTTP 代理。
- 完整浏览器与 HTTP Cookie 双向同步、未证实的私信端点或跨插件认证服务发布。
- 既有外观、调优、技能管理的功能重构或无关缺陷修复。
