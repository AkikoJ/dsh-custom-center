# 01: 打通最小登录与 HTTP 验证闭环

Type: task
Status: ready-for-human
Blocked by: None (can start immediately)

**What to build:** 用户从独立「抖音账号」设置页打开真实登录窗口，在网页完成登录后手动检查；宿主确认账号 UID、保存内部凭据，并以独立 Node HTTP 请求确认同 UID。页面分别反馈窗口、浏览器认证、凭据保存和 HTTP 验证状态，形成最小可演示闭环。

依据父规格《抖音账号登录与宿主内部凭据》、领域词汇表及 ADR-0002、ADR-0003。本任务先证明 Chromium、平台身份响应和独立 HTTP 链路可行；自动观察、完整异常恢复与安装整体验收由后续任务扩展。

- [x] 在既有设置插槽新增「抖音账号」入口及打开、检查、关闭操作；进入页面仅查询状态，不启动浏览器或下载软件，不提供密码、验证码或 Cookie 输入框。
- [x] 使用 Node.js + Playwright 及匹配的配套 Chromium；浏览器能力延迟加载。缺少浏览器时提示明确准备步骤，启动失败与导航失败分别反馈，其他中心功能仍能使用。
- [ ] 打开操作在可见的专用持久上下文实际启动并导航至固定抖音网页后才报告开窗成功；用户在网页完成扫码、手机确认、短信或验证码。上下文使用服务端决定且按 DSH profile 隔离的数据根，不使用个人 Chrome profile。
- [ ] 当前账号候选接口经过实际核实，以平台业务成功及非空 UID 确认身份；昵称可缺省。Cookie 非空、头像或 Cookie 中的用户字段均不能单独产生登录成功。
- [x] 身份验证完成后读取含 HttpOnly 的 Cookie，保存身份与凭据同属一份原子快照，包含 schema、凭据代次、UID、可选昵称、导出及浏览器验证时间、User-Agent 和完整 Cookie 属性。使用临时写入后替换、仅当前用户访问的目录和 0600 文件权限。
- [x] Cookie 保留域、路径、期限、HttpOnly、Secure、SameSite 及可获得的扩展属性；从第一版即使用成熟 CookieJar 按目标匹配，只允许明确抖音域，逐跳校验重定向。不扁平拼接跨域 Cookie，不将不支持的分区 Cookie 当普通 Cookie 使用。
- [x] 独立 Node HTTP 客户端只读取已保存的内部凭据，不使用浏览器共享认证请求上下文；平台业务成功且 UID 一致才显示 HTTP 已验证，结果记录账号、凭据代次及验证时间。
- [x] 浏览器身份确认且保存成功即完成登录；HTTP 临时失败显示「HTTP 待验证」，不强迫重新扫码。明确未登录或 HTTP UID 不一致时停止相关凭据的内部消费，发现另一个账号不静默覆盖一期账号。
- [x] 保存失败不得报告本次凭据成功；快照存在不等于当前有效。凭据仅供宿主内部，不提供下载、复制、通用代理、跨插件凭据服务或 Agent 工具。
- [x] 提供状态、开窗、检查及关窗的受控宿主路由；产生副作用前验证回环 socket、宿主认证及来源接受结果、同源请求标记；禁止缓存，不接受任意 URL、文件路径、执行路径或 JavaScript。正常及错误响应、日志、Agent 上下文均不包含凭据或完整平台响应。
- [x] 单服务实例管理一个上下文，重复开窗复用、检查串行或合并、关闭幂等且保留会话；不自动切换无头浏览器。至少提供所属上下文及任务的 effect 清理，后续任务补齐竞态恢复。
- [x] 以宿主 HTTP 路由为主要自动化入口，保留真实编排、CookieJar 与临时目录，仅替换浏览器及平台网络边界；覆盖真正启动和导航后开窗成功、身份候选不充分、保存、同 UID 独立 HTTP 成功、临时失败和拒绝请求无副作用。检查实际出站 Cookie 及最终快照，不断言私有方法或内部调用次序。
- [x] 架构检查识别新功能，保持浏览器侧无 Node/服务端依赖、共享模块不反向依赖功能、功能无不当交叉引用及源码无环；不运行时引用两个参考插件，不引入 Python/MCP。
- [ ] 在已明确准备好资源且获得实际用户登录配合的 macOS DSH 环境，记录一次真实 Chromium 开窗、浏览器身份确认与独立 Node HTTP 同 UID 成功的脱敏证据及环境版本。模拟测试不能替代技术可行性证据；需要超出范围的签名或协议工作时记录具体阻塞，不降低身份判定标准。
- [x] 验证使用非构建型类型检查及针对性测试；安装浏览器属于明确准备步骤，构建须另获用户明确要求或批准。当前任务不实现私信、多账号、清除登录或其他平台支持。
