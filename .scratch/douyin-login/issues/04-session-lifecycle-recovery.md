# 04: 实现会话恢复与可靠资源清理

Type: task
Status: ready-for-human
Blocked by: 01

**What to build:** 用户关闭窗口或重启宿主后仍保留专用浏览器会话；页面区分上次资料与本次有效性，并在重复操作、profile 占用、保存故障和热更新后提供可恢复的反馈，不留下重复窗口或过期状态写回。

依据父规格《抖音账号登录与宿主内部凭据》及 ADR-0003，扩展任务 01 的基本持久化与清理。此任务可通过关窗重开、宿主重启和故障恢复独立验收，无须等待自动观察或完整 HTTP 异常分类。

- [x] 关闭窗口保留专用持久会话及快照，重复关闭幂等；重新打开复用同一 profile，不自动切换无头模式，不改动个人浏览器数据。
- [x] 宿主重启只恢复历史保存摘要，当前浏览器认证与 HTTP 可用性保持未验证；必须经过实际身份检查才能恢复当前有效结论。
- [x] 不同 DSH profile 使用隔离的服务端数据根；无 profile 时有明确宿主数据根回退，页面不能指定存储位置，目录及凭据文件权限满足父规格要求。
- [x] 损坏、缺字段或不支持 schema 的快照不提供给业务，页面可诊断并继续登录；不因资料文件存在而报告登录成功。
- [x] 写入失败保留上一份完整快照，明确标记本次保存失败，不能将旧资料冒充本次成功；重试后身份、Cookie 与代次保持原子一致。
- [x] 并发开窗只产生一个受管理上下文，开窗、检查、保存、关闭协调串行或合并；关闭及重新打开时旧异步任务失去写回资格。
- [x] profile 占用时给出明确恢复提示，不删除锁文件、不终止其他浏览器进程，不以新目录隐式绕开已绑定账号。
- [x] 插件卸载、宿主停止和 HMR 清理所属窗口、定时器及请求；新实例等待旧上下文释放才复用 profile，旧实例不能覆盖新实例状态或凭据。
- [x] 从宿主 HTTP 路由及真实临时目录验证重启语义、不同 profile 隔离、损坏及未知 schema、原子替换失败、重复操作、并发关开、清理与过期写回；复用既有 effect 和延迟响应测试模式，不为私有 helper 增设测试接口。
- [ ] 在 macOS DSH 中记录关窗重开及重启后会话保留、当前状态重新验证的脱敏结果；未实际验证的 HMR 或 profile 争抢场景保留明确待验收记录，不以模拟测试替代运行证据。
