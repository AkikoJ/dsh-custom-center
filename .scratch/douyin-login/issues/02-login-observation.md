# 02: 自动观察登录并支持继续验证

Type: task
Status: ready-for-human
Blocked by: 01

**What to build:** 用户打开登录窗口后，在同一网页完成扫码、手机确认、短信或验证码，设置页自动反映身份确认、凭据保存及独立 HTTP 验证结果；等待过久只暂停观察，用户可手动继续验证而不丢失已有网页步骤。

依据父规格《抖音账号登录与宿主内部凭据》及 ADR-0003，扩展任务 01 的手动闭环。此任务可独立演示从等待扫码到状态自动更新，再到观察暂停及手动恢复的完整过程。

- [x] 开窗后启动有界自动观察，能在可信平台身份成功后自动触发凭据保存和必要的独立 HTTP 验证；自动与手动检查复用相同身份及凭据规则。
- [x] 等待期间提供清楚提示，引导用户在浏览器或手机继续操作；无法识别具体验证类型时保留网页操作，不重置登录、不提前判定失败或成功。
- [x] 初始节奏为约 3 秒轻量观察、至少间隔 10 秒身份验证，临时失败退避，单次网络请求约 15 秒超时；观察串行，不因慢响应叠加请求。
- [x] 等待用户约 10 分钟后暂停自动观察并明确显示原因，保留窗口、持久会话及已完成步骤，不自动关窗或开启新上下文。
- [x] 暂停后「检查登录状态」仍可继续确认身份、保存及 HTTP 验证；重复操作不会重置扫码流程或生成重复任务。
- [x] 页面分别展示等待、浏览器已确认、保存成功或失败、HTTP 已验证或待验证，不能因 HTTP 暂时失败撤销已确认的浏览器登录。
- [x] 离开设置页取消页面刷新及请求，延迟响应不能写回卸载页面；重新挂载只查询现有状态，不自动开窗，也不重复创建宿主观察任务。
- [x] 自动观察在关窗、服务清理或明确失效时停止；检查与关窗并发时不产生关闭后的新请求或状态回退。
- [x] 从宿主路由入口通过可控浏览器和平台响应验证等待、自动完成、超时暂停、手动继续、并发检查及资源取消，保留真实编排和临时凭据存储；必要时仅补充无法由宿主入口覆盖的页面卸载及延迟响应测试。
- [ ] 在真实 macOS DSH 页面演示自动状态反馈、等待提示和手动继续；仅记录实际观察到的认证方式，未实际触发的短信或验证码流程不得宣称已实测。
